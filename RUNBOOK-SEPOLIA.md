# Runbook: free rehearsal on Sepolia

Cost: zero. Sepolia STRK comes from the [Starknet faucet](https://faucet.starknet.io).
Two paths, run B first:

| Path | Pool | Proves | Depends on |
|---|---|---|---|
| **B · MockPool** | Test-only contract seeded with StarkWare's reference note | The real SNIP-36 path: virtual OS, stwo prover, `register_receipt` accepting real proof facts on chain | snip36 + a Sepolia RPC only |
| **A · Real pool** | The STRK20 pool on Sepolia | Everything in B, plus a real private payment created through the pool | StarkWare's Sepolia prover and discovery services being reachable |

## 0. Tools and repo (as in RUNBOOK.md steps 0 and 1)

`.env` for Sepolia:

```
STARKNET_CHAIN_ID=SN_SEPOLIA
STARKNET_RPC_URL=https://starknet-sepolia-rpc.publicnode.com
PRIVACY_SDK=<path>/starknet-privacy/sdk
```

Pool, prover and discovery URLs default to the Sepolia values for `SN_SEPOLIA`.

## Before proving: three facts measured on Sepolia (2026-10-19)

- **RAM.** The snip36 runner is a ~15 GB process. On an 8 GB laptop it is killed mid-proof
  (`connection closed before message completed`). Use a 16 GB+ machine, or the CI workflow below.
- **RPC for the prover.** It needs `starknet_getStorageProof` at the base block. PublicNode serves only
  `latest`; ZAN (`https://api.zan.top/public/starknet-sepolia/rpc/v0_10`) keeps ~128 blocks (~3.5 min).
  Start `snip36 prove` right after `03` and pass `--rpc-url` with the ZAN endpoint. Other steps can use PublicNode.
- **Validity window.** Sepolia runs at ~1.7 s per block, so 450 blocks is ~13 min. For rehearsals deploy the
  receipt contract with `--validity 3000` (~85 min).

## Path B in CI (no local prover needed)

`.github/workflows/sepolia-receipt.yml` runs 03 → prove → 04 `--send` → 05 → tamper check on a GitHub runner
(16 GB RAM + swap) and puts the tx link in the run summary. Path B's note is StarkWare's public reference
vector, so the prover input holds no secret; never run a real channel key through a hosted runner.
Repo secrets: `STARKNET_ACCOUNT_ADDRESS`, `STARKNET_PRIVATE_KEY` (Sepolia test account only). Run it from
Actions → "Sepolia receipt" → Run workflow; the MockPool and receipt addresses are inputs.

## Path B · MockPool (do this first)

```bash
cd ../contracts && scarb build && cd ../client
npx tsx scripts/00-deploy-mock-pool.ts       # ✔ prints POOL=0x…  → add to ../.env ; writes private-note.json
npx tsx scripts/00-deploy-receipt.ts --validity 3000   # ✔ prints RECEIPT_CONTRACT=0x… → add to ../.env
npx tsx scripts/03-make-virtual-tx.ts --note private-note.json --claim atLeast:900 --reference INV-TEST-1
snip36 prove virtual-os --block-number <BASE_BLOCK> --tx-json out/receipt_tx.json \
  --rpc-url https://api.zan.top/public/starknet-sepolia/rpc/v0_10 --output out/receipt.proof
npx tsx scripts/04-register-receipt.ts       # ✔ two OK lines
npx tsx scripts/04-register-receipt.ts --send   # ✔ registered_at(commitment) > 0
npx tsx scripts/05-verify.ts --opening out/opening.json --rpc "$STARKNET_RPC_URL"   # ✔ VERIFIED
```

Tamper check: copy `out/opening.json`, change `claim.value` to `901`, run `05-verify.ts` on the copy → ✔ `opening does not match`.
Run `04` within the validity window of the base block; if it is late, re-run `03` and prove again.

**What B proves:** a stwo proof of `prove_payment` generated by the real snip36 prover, accepted by Sepolia, and the receipt verified from its opening alone.
**What it does not:** that the note came through the real pool (that part is covered by the tests against StarkWare's pool contract).

## Path A · Real Sepolia pool

```bash
# 1. remove the POOL= line from ../.env (back to the real Sepolia pool), then:
npx tsx scripts/00-deploy-receipt.ts                     # new RECEIPT_CONTRACT for the real pool → ../.env
npx tsx scripts/01-register.ts && npx tsx scripts/01-register.ts --send    # ✔ Registered

# 2. a second account that pays privately
cp ../.env ../.env.sender && sed -i.bak '/STARKNET_PRIVATE_KEY\|STARKNET_ACCOUNT_ADDRESS\|RECEIPT_CONTRACT/d' ../.env.sender
npx tsx scripts/00-account.ts --new --env ../.env.sender  # faucet → this address too
npx tsx scripts/00-account.ts --deploy --env ../.env.sender
npx tsx scripts/01b-pay.ts --env ../.env.sender --to <receipt account address> --amount 1000000000000000000
npx tsx scripts/01b-pay.ts --env ../.env.sender --to <receipt account address> --amount 1000000000000000000 --send

# 3. receipt, as in path B
npx tsx scripts/02-find-notes.ts --pick 0 --out private-note.json
npx tsx scripts/03-make-virtual-tx.ts --note private-note.json --claim atLeast:500000000000000000 --reference INV-TEST-2
snip36 prove virtual-os … ; 04 ; 04 --send ; 05
```

If the Sepolia prover or discovery service refuses (HTTP error, 401/403, OHTTP error), try `PROVING_OHTTP=true` /
`DISCOVERY_OHTTP=true` in the env file; if it still refuses, these services are not open to us and path B is the result.

## Keep for the application

- `MockPool`, `PaymentReceipt` addresses and the `register_receipt` tx hash (path B)
- The same from path A, if it ran
- The `05-verify.ts` output and the tamper-check output

## If something fails

Send the full command output, never the env files or `private-note.json`.
Likely spots: the account class not accepted by the virtual OS (step 1), the RPC missing a method the prover
needs (try the Alchemy or Blast Sepolia endpoints), a late `04` (re-run `03`).
